# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A port of the Halo: Combat Evolved decompilation (Xbox build 2342, `cachebeta.exe`) to Linux (32-bit x86), Windows
(32-bit x86) and Android (arm64 app running ILP32 AArch64 code), all on SDL3 and OpenGL 4.5 / OpenGL ES 3. The game
data is not in the repo; the game extracts `maps/` from a user-supplied Xbox disc image at first start.

The READMEs are the design documentation and are detailed: `README.md`, `port/linux/README.md` (controls, settings,
netcode, and "How the port operates"), `port/windows/README.md`, `port/android/README.md`, `port/linux/NETCODE.md`,
`port/include/xdk/README.md`, `tools/harness/README.md`. Read the relevant "How the port operates" section before
changing build flags or the platform layer.

## Build

```sh
python configure.py [--release] [--portable] [--lto=thin|off] [--pgo=off|train] [--compiler-launcher=ccache]
ninja linux            # build/linux/halo
ninja windows          # on Windows: build/windows/halo.exe + SDL3.dll
ninja android_apk      # port/android/app/build/outputs/apk/debug/app-debug.apk
```

- Default (no `--release`) is a debug build where a failed assertion stops the game; `--release` skips assertions.
- Without `--portable`, Linux/Windows build with `-march=native`. `--portable` on Linux also builds against Debian 11's
  glibc and bundles SDL3 (`tools/linux_sysroot.py`; first build downloads them, needs CMake, pkgconf, wayland-scanner).
- `--lto=full` is the default and links slowly; use `--lto=thin` or `--lto=off` for faster iteration.
- PGO uses `pgo/halo_linux.profdata` (Linux, Android) and `pgo/halo_windows.profdata`; needs clang 22+, otherwise skipped.
- `build.ninja` regenerates itself when `configure.py` or the `tools/*_build.py` inputs change.
- `python tools/ci_build.py <linux|windows|android> <debug|release>` reproduces a CI build into `dist/`.

## Tests

CI (`.github/workflows/build.yml`) runs on Linux:

```sh
python -m pytest -q tools/test_linux_port.py tools/test_host_watch_hash.py tools/harness
python tools/test_light_storage.py
```

Single test: `python -m pytest -q tools/harness/tests/test_mixer.py -k <case>`.

Tests need `clang` (or `CC`) and a 32-bit C runtime (`lib32-glibc` / `gcc-multilib`). `tools/harness` is the
asset-free regression harness: each test pulls real functions, enums and constants out of `source/` or `port/`
(`function`, `inline`, `enum_with`, `constant`) rather than copying them, compiles them against a minimal fake world
(`tests/<name>.c`), and must include a negative control (`mutated`) proving a deliberate fault fails a `CHECK`. pytest
discovers any new `tests/test_*.py` without CI changes. Things that need real maps are checked in-game instead
(offline: `debug.null_renderer`).

## Architecture

**`source/`** — the decompiled game (C, written for MSVC and the Xbox XDK). Mostly reproduces the original machine
code; port changes are kept minimal and listed in the "Game source changes" tables of the platform READMEs (update
those tables when you change game behaviour in `source/`). Platform-specific code uses `HALO_ANDROID`,
`HALO_WINDOWS`, `HALO_RELEASE`. All `.c` under `source/` are compiled except the exclusions in
`port/linux/port.json`, which also holds the game's defines and include dirs (shared by all three ports).

**`port/include/xdk/`** — clean-room stand-ins for the Xbox SDK headers (`xtl.h`, D3D8, DirectSound, Winsock, XBDM).
`xdk_pdb.h` is generated by `tools/xdk_headers.py` from the original PDB (add names to `pdb_names.txt`); the rest are
hand-written from public sources. Never derive anything from the real SDK headers.

**`port/linux/src/`** — the platform layer shared by all ports: implements the XDK APIs the game calls. D3D8 is
emulated on OpenGL (`d3d8_gl.c`, NV2A shader translation in `nv2a_vsh.c`/`nv2a_psh.c`), DirectSound on SDL
(`dsound_sdl.c`), input via SDL (`xinput_sdl.c`), Xbox kernel/memory/files (`xbox_*.c`), disc extraction (`xiso.c`),
internet play (`p2p*.c`), self-updater, and settings (`port_config.c`: every `config.toml` setting with its default
and `HALO_*` env override). Files named `posix_*.c` use the host ABI and glibc; the rest include `platform.h` and are
compiled with the game's MSVC-like ABI so definitions are checked against the XDK prototypes.

**`port/linux/game/`** — port-added game features compiled with the game ABI: distributed netcode and co-op
(`network_*.c`, `coop_*.c`), Custom Edition map loading (`custom_edition_*.c`, see `docs/custom_edition_caches.md`),
tag schema validation, PC-style menus (`menu_*.c`), hi-res HUD, render interpolation, `msvc_comdat.c`.

**MSVC ABI emulation** — the game's data (cache files, saved games, D3D resources) holds 32-bit pointers and Xbox
memory layouts, so every port runs 32-bit-pointer code with MSVC structure layout:
- Linux: clang `--target=i686-linux-gnu -fms-extensions -fshort-wchar -malign-double -fcommon -freg-struct-return`,
  plus `port/linux/include/halo_linux_prefix.h` (first header of every file), `tools/linux_msvc_semantics.py`
  (file-scope struct tags, weak header inlines as COMDAT), and `tools/linux_link_check.py` (fails the link on an
  undefined weak reference, which would otherwise resolve to 0).
- Windows: clang `i686-pc-windows-msvc`; `port/windows/port.json` lists the Linux platform files it replaces with
  `port/windows/src/win32_*.c`; `halo_windows_prefix.h` renames XDK functions to reach real Win32.
- Android: the "guest" (game + platform layer + musl for a custom `arm64_32` arch in `port/android/guest/`) is compiled
  for `arm64_32-apple-watchos`, converted from Mach-O to ELF assembly (`tools/android_asm_convert.py`), and linked to
  a static image loaded at a fixed address by the arm64 "host" `libmain.so` (`port/android/host/`), which reserves
  guest memory below 4 GB (Xbox memory at `0x80000000`) and services syscalls, SDL, GLES and `posix_*` calls via
  generated stubs (`tools/android_imports.py`, `android_gl_stubs.py`, `android_posix_stubs.py`). The ILP32 ABI passes
  floats and varargs differently from x86, so mismatched prototypes break calls; `tools/android_abi_check.py` detects
  them.

**Build generators** — `configure.py` delegates to `tools/linux_build.py`, `tools/windows_build.py`,
`tools/android_build.py`, which emit ninja rules via `tools/ninja_syntax.py`. Embedded assets (HUD, menus, fonts,
titles, icons from `port/assets/`) are generated by `tools/embed_assets.py`, `ce_menus.py`, `port_settings.py`, etc.

**Handicaps (this fork's feature)** — per-player health/shield multipliers for multiplayer, set by the host by
player name in `config.toml`'s `[handicap]` or the console's `handicap <name> <multiple>`.
`port/linux/game/handicap.c` looks them up; `game_engine_get_damage_multiplier` (`source/game/game_engine.c`) divides
the damaged player's damage by it, and `game_engine_game_starting` re-reads the table. Only the host applies them
(the netcode is host-authoritative for damage), so nothing goes over the network and the network version is
unchanged. `[handicap]` is a "table of names" in `port_config.c` (`config_table_numbers`,
`config_table_write_number`), exempt from the unknown-setting check. Tests: `tools/harness/tests/test_handicap.py`,
`test_config_tables.py`. Docs: "Handicaps" in `port/linux/README.md`. CI builds update from the repository that built
them (`HALO_UPDATE_REPOSITORY`, set by `tools/ci_build.py`), so fork builds don't update to upstream.

**In-game testing without the menus** — `debug.network_test` (`port/linux/game/network_test.c`): e.g. a host with
`HALO_NETWORK_TEST=host:bloodgulch` and a client with `HALO_NETWORK_TEST=join` on separate loopback addresses (see
"Play on one computer"), plus `HALO_NETWORK_TEST_SHOOT=<seconds>`, `HALO_HIDDEN_WINDOW=1`, `HALO_NULL_RENDERER=1`;
each second they log every player's body/shield vitality. `HALO_DATA_ROOT` points at the folder holding `maps/`;
`debug.txt` there is the game's log, while `platform_log` goes to stderr. `debug.exit_after` does not end a hidden
window's game, so wrap each process in `timeout`.

**`port/third_party/`** — vendored libraries (mbedtls, monocypher, opus, kcp, miniupnpc, tomlc17, zlib, stb, smaa,
expat, extract-xiso, musl-math).

## Conventions

- Documentation is written in short, plain, simplified-technical English (see the READMEs); comments in code are full
  sentences explaining why. Match the surrounding style.
- Commit subjects are short descriptive phrases, often with the PR number, e.g.
  `Scripted first-person cameras blended as before (#189)`.
- CI ignores pushes that only touch `*.md`. Each `main` build passing on all three platforms becomes a GitHub release.
